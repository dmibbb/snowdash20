## Фаза 1: Setup & Skeleton -- ГОТОВО

Цель: рабочее приложение с пустым canvas и игровым циклом.
Результат: npm run dev — страница с canvas 800×600, tick() вызывается 20 раз/сек, в консоли чисто.

Подзадачи:

- Vite + TS шаблон, ESLint + Prettier.
- index.html, main.ts, <canvas 800×600>, CSS-центрирование с image-rendering: pixelated.
- config.ts со всеми константами.
- rAF-цикл с аккумулятором → tick() каждые 50 мс.

DoD: canvas по центру, tick() в консоли, npm run build собирается.

## Фаза 2: Player on Empty Grid -- ГОТОВО

Цель: пустое поле + игрок-плейсхолдер (синий квадрат 40×40), ходящий по клеткам.
Результат: стрелки/WASD двигают игрока, он останавливается в клетке и не выходит за поле.

Подзадачи:

- Отрисовка пустого поля (фон + сетка).
- Класс Player: пиксельные координаты, state: idle/moving, direction.
- Input: keydown/keyup, preventDefault на стрелках, сброс на blur.
- Движение 2 px/тик, стоп ровно в клетке.
- possibleDirection — проверка границ карты.

DoD: игрок ходит по полю, не выходит за края, останавливается в клетках.

## Фаза 3: Level Loading & Walls -- ГОТОВО

Цель: парсер текстового уровня + рендер стен, снега, сундуков. Игрок не проходит сквозь стены.
Результат: первый уровень из .txt отображается, стены блокируют движение.

Подзадачи:

- Парсер parseLevel(text) с валидацией (13×20, одна P).
- Юнит-тесты парсера (Vitest).
- Класс Level: сетка, getCell, isPassable.
- Загрузка level01.txt из public/levels/.
- Рендер статических тайлов + проверка стен в possibleDirection.

DoD: уровень виден, в стены не пройти, тесты парсера зелёные.

## Фаза 4: Tiles Interactions -- ГОТОВО

Цель: снег съедается, сундуки собираются, счёт растёт.
Результат: полный геймплейный цикл «собрать все сундуки».

Подзадачи:

- Счёт и visibleChests в простом state.
- Снег → Empty при Idle-тике.
- Сундук → +30 очков, visibleChests--, клетка Empty.
- Триггер в possibleDirection (не по нажатию клавиши, а на каждом Idle-тике).
- DoD: собрав все сундуки, visibleChests == 0, счёт растёт.

## Фаза 5: Stones

Цель: физика камней — падают, скатываются с края, толкаются игроком, убивают игрока.
Результат: все состояния Idle / Falling / Pushed работают.

Подзадачи:

- Класс Stone + отрисовка.
- Падение вниз (8 px/тик), приземление.
- Падение вбок с края (5 px/тик в сторону → 8 вниз).
- Толкание игроком (5 px/тик).
- Коллизия Stone ↔ Player → урон при Falling или Pushed.

Актуальные скорости смотри по спеке.

DoD: камень падает, катится, толкается, убивает игрока.

## Фаза 6: Monsters

Цель: монстры блуждают, опасны для игрока, умирают от камней.
Результат: полный геймплей с угрозой и возможностью убивать камнями.

Подзадачи:

- Класс Monster + движение 1 px/тик + анимация.
- Блуждание + выбор нового направления при блокировке.
- Monster ↔ Player → урон игроку.
- Monster ↔ Monster → оба выбирают новое направление.
- Stone ↔ Monster → смерть + очки (35/25 по модели).

DoD: монстры двигаются, убивают игрока, умирают от камней, очки начисляются.

## Фаза 7: Game State & Progression

Цель: жизни, рестарт уровня, переходы между уровнями, рейтинг.
Результат: игра «закольцована» — проигрыш / проход / переход.

Подзадачи:

- Класс Game: score, lives, levelIndex, все сущности.
- Потеря жизни → сброс всех на стартовые позиции, счёт сохраняется.
- Уровень пройден (visibleChests == 0) → +50 очков, следующий.
- После 10-го уровня → Game Over с рейтингом 9.
- getRating(levelIndex) по таблице.

DoD: 10 уровней проходятся, жизни тратятся, при 0 — Game Over с рейтингом.
